# Appendix G: Task Structure Reference

| Element | Description |
|---------|-------------|
| **Title** | Verb-phrase describing the change |
| **[Parent](/ubiq/#parent-task)** | [Use Case](/ubiq/#use-case) ID or [Story](/ubiq/#story) ID |
| **[Inputs](/ubiq/#inputs)** | What the Task needs to start |
| **[Outputs](/ubiq/#outputs)** | What the Task produces |
| **[Constraints](/ubiq/#constraints)** | Boundaries, [business rules](/ubiq/#business-rules), design decisions |
| **[Acceptance criteria](/ubiq/#acceptance-criteria)** | Lightweight, Task-level pass/fail conditions |
| **[Definition of Done](/ubiq/#definition-of-done)** | Checklist for Task completion |

[Tasks](/ubiq/#task) live under their parent Use Case or Story. They are the unit of assignment and tracking during the [Build Phase](/delivery/#build-phase).
