# Appendix G: Task Structure Reference

| Element | Description |
|---------|-------------|
| **Title** | Verb-phrase describing the change |
| **[Parent](/reference/ubiq/#parent-task)** | [Use Case](/reference/ubiq/#use-case) ID or [Story](/reference/ubiq/#story) ID |
| **[Inputs](/reference/ubiq/#inputs)** | What the Task needs to start |
| **[Outputs](/reference/ubiq/#outputs)** | What the Task produces |
| **[Constraints](/reference/ubiq/#constraints)** | Boundaries, [business rules](/reference/ubiq/#business-rules), design decisions |
| **[Acceptance criteria](/reference/ubiq/#acceptance-criteria)** | Lightweight, Task-level pass/fail conditions |
| **[Definition of Done](/reference/ubiq/#definition-of-done)** | Checklist for Task completion |

[Tasks](/reference/ubiq/#task) live under their parent Use Case or Story. They are the unit of assignment and tracking during the [Build Phase](/guide/delivery/#build-phase).
